# E1002 도착 후 순서

이 문서는 아직 수행하지 않은 실기기 검증입니다. 빌드 성공은 아래 항목의 정상 동작 증명이 아닙니다.

## 1. 최초 USB 업로드

- [ ] 충전 및 전원 스위치 ON. microSD는 첫 시험에서 제거.
- [ ] setup.bat로 2.4GHz SSID/비밀번호/실제 iCloud 공개 URL 준비.
- [ ] `pio run` 성공 → USB-C 데이터 케이블 → Upload.
- [ ] 115200 모니터에서 power/reset, PSRAM 크기(실제 장착 확인), Clock, Feed, Display, Sleep 로그 확인.
- [ ] 800×480 가로 방향, 6색 패널 중 빨강/파랑, 한글 검은 배경 없는지 확인.
- [ ] refresh에 걸리는 시간 및 `Busy Timeout!` 유무 기록. 갱신 도중 전원 차단 금지.
- [ ] 버튼과 케이블이 막히지 않는 위치에서 충분히 검증한 후 냉장고에 부착.

화면이 안 바뀌면 바로 SPI 속도를 높이지 않습니다. 전원/CS/BUSY/패널 모델을 확인하고, 보드 편차가 의심되면 initDisplay의 SPISettings를 2MHz에서 200kHz로 내려 비교할 수 있습니다. 기본값은 공식 예제의 2MHz입니다.

## 2. 일정 정확성

iCloud에 시험 전용 일정을 생성하고 Apple Calendar와 비교합니다.

- [ ] 오늘 종일, 시간 지정, 한국 자정 전후 UTC 일정.
- [ ] 3일 종일 일정의 종료일 전날까지 표시(DTEND 제외).
- [ ] 매일/매주 다중 요일/격주/매월 둘째 월요일/매년 생일.
- [ ] 1회 수정(날짜 이동), 1회 취소, COUNT 종료, UNTIL 종료, EXDATE.
- [ ] 1·2·3·4개 및 15개 일정의 줄바꿈/`+N` 정확성.
- [ ] 긴 한글, 영어, 공백, 미지원 이모지 `?`, 제목 없는 일정.
- [ ] 해당 기간 공휴일과 대체공휴일을 실제 달력과 비교.
- [ ] 수정/삭제 후 KEY0를 **짧게 누르고 놓아** 새 화면 반영. iCloud 공개 피드 자체의 반영 지연도 고려.

미지원 속성/외국 TZID가 포함되면 피드 전체를 거절할 수 있습니다. 실제 피드가 필요하지만 이 작업에는 사용자 공개 URL이 제공되지 않았으므로 이 부분은 PC 가상 ICS 검증만 완료했습니다.

## 3. 실패 복구

- [ ] 정상 화면이 나온 뒤 Wi-Fi를 끄고 KEY0 → 기존 화면 유지.
- [ ] Wi-Fi를 복구하고 KEY0 → 갱신.
- [ ] 캘린더 2개 중 한 링크를 잘못 설정 → 기존 전체 달력 유지.
- [ ] HOLIDAY_ICS_URL을 일시적으로 실패하는 HTTPS 주소로 설정 → 개인 일정 갱신, 캐시 공휴일 유지, 우측 작은 빨간 점.
- [ ] 기본 공휴일 소스로 복구 → 정상 동기화 및 빨간 점 제거.
- [ ] 잘린 ICS/HTML 오류 응답을 정상 빈 달력으로 오인하지 않음.
- [ ] KEY0를 누른 채 기다려도 계속 깨어나는 루프가 없음(이 경우 다음 sleep에서는 timer만 활성).

## 4. Sleep/USB/24시간

- [ ] USB를 뽑은 배터리 단독 상태에서도 화면 유지 및 KEY0 wake.
- [ ] USB 연결 상태에서도 동기화 후 sleep. USB CDC 포트 해제/재열거 확인.
- [ ] 실제 24시간 후 timer wake 및 오늘 테두리 이동.
- [ ] 일요일을 지난 뒤 6주 표시 범위 한 주 이동.
- [ ] 같은 날짜에 RESET으로 동일 데이터를 재조회하면 refresh 생략. KEY0는 강제 refresh.
- [ ] 필요하면 AUTO_SYNC_HOURS=1로 timer 시험 후 **24로 복원**. 분 단위 시험은 코드를 별도 변경해야 하며 기본 설정은 1~168시간만 허용.

## 5. 전류 측정

USB 측정값은 충전회로/USB 전력까지 포함합니다. 배터리 수명 판단에는 **USB를 분리한 배터리 입력 전류**를 측정합니다. 순간 피크를 버틸 계측기를 쓰고 전류계 삽입으로 brownout이 생기지 않는지 확인합니다.

| 측정 구간 | 기록할 값 |
|---|---|
| 부팅/PSRAM 초기화 | 피크 mA, 지속 시간 |
| Wi-Fi 연결 및 NTP | 평균/피크 mA, 연결 초 |
| 각 ICS TLS/다운로드 | 소요 초, free heap/min heap, free PSRAM |
| Wi-Fi OFF 후 E-Ink 전체 refresh | 평균 mA, refresh 초, BUSY timeout |
| hibernate 후 1분 이상 Deep Sleep | 안정된 µA/mA, LED 꺼짐 |
| 동일 화면으로 refresh 생략 | 전체 깨어 있던 시간 및 소비량 |
| Wi-Fi 실패/KEY0 장시간 눌림 | 타임아웃 후 실제 sleep 여부 |

일일 소비량은 `활성구간 합계(mA×초)/3600 + sleep전류(mA)×sleep시간(h)`로 산출합니다. 외부 pull-up, RTC_PERIPH 유지, LED/SD/배터리 측정 회로 및 USB 영향을 포함한 실제 측정 전에는 배터리 수명을 보장하지 않습니다. 내부 RTC pull-up의 확실한 유지를 우선하여 RTC_PERIPH를 ON으로 두었으므로 추가 절전 여지는 실측 후 판단합니다.
